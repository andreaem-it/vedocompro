# AGENT_SYNC — Coordinamento tecnico Claude ↔ Codex

File condiviso tra Claude Code e Codex (o altri agenti AI) per evitare lavori duplicati,
perdite di contesto e sprechi di token. **Prima di iniziare qualsiasi task, leggi questo
file e aggiornalo al termine del tuo turno.**

---

## Protocollo di aggiornamento

1. **Leggi prima di scrivere** — controlla il campo `IN_PROGRESS` per capire se l'altro
   agente sta già lavorando su qualcosa di correlato.
2. **Dichiara l'intenzione** — prima di iniziare un task non banale, aggiungi una riga in
   `IN_PROGRESS` con il tuo nome (Claude/Codex) e una descrizione breve. Questo vale come
   "lock" informale.
3. **Aggiorna al termine** — sposta la voce da `IN_PROGRESS` a `DONE` o `NOTES`, con la
   data e un riassunto tecnico del come/perché.
4. **Non sovrascrivere le note altrui** — appendi, non sostituire.

## Convenzioni di codice stabilite

- **Controller**: `nomeRisorsa.controller.ts` (pubblico) / `admin-nomeRisorsa.controller.ts` (admin)
- **Route**: `api/src/routes/` + registrazione in `routes/index.ts`
- **Autorizzazione**: `requireAuth` (JWT), `requireAdmin` (`user.isAdmin`), `requireSuperAdmin` (`user.isSuperAdmin`)
- **Campi modificabili utente**: ogni controller espone una whitelist `USER_EDITABLE_FIELDS` per evitare che un utente si auto-imposti campi privilegiati (es. `isAdmin`, `isCompany`)
- **Notifiche in-app**: usa sempre le costanti di `api/src/constants/notifications.ts`, mai magic number
- **Feature flags**: `SHOP_ENABLED` (API) + `NEXT_PUBLIC_SHOP_ENABLED` (web) — pattern da replicare per future feature opzionali
- **Cron jobs**: endpoint `GET /cron/nome-job` protetti da header `Authorization: Bearer CRON_SECRET`
- **Colore brand**: `#4396c1` (chiaro) / `#236abd` (scuro) — configurato in `tailwind.config.ts` come `brand-*`
- **Admin UI**: classi Tailwind `.admin-box`, `.admin-breadcrumb`, `.admin-small-box` in `globals.css` per uniformità AdminLTE
- **Test**: unit test vitest in `api/src/**/__tests__/*.test.ts` con mock di `lib/prisma` via `vi.mock` (nessun DB reale). Prima di chiudere una voce: `npm test` in `api/` oltre a `tsc --noEmit`. Se tocchi antispam/rate-limit/ad-fields, aggiorna i test relativi.
- **Rate limiting**: sempre DB-based (tabelle dedicate tipo `auth_attempts`), mai in-memory — l'API è serverless

## Note tecniche da tenere a mente

- `prisma db push` va eseguito manualmente prima del deploy ogni volta che si aggiunge un campo o modello — non c'è auto-migrate in produzione.
- Il seed (`api/prisma/seed.ts`) popola categorie + dati geografici (comuni/province/regioni) da `legacy-symfony/web/json/` — non alterare quei JSON.
- I cron Vercel (`api/vercel.json`) scadono a 60s su piano Hobby; i job video vengono eseguiti in batch da 2 per rispettare il timeout.
- Il frontend usa `fetch` diretto verso `API_URL` — non c'è un BFF separato.
- `web/src/app/layout.tsx` include `SiteChrome.tsx` che nasconde header/footer su `/admin/*`.
